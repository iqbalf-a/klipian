## What went wrong with opencode (read from its answer and `remotion/sleep-inertia-brief.json`; every point is a defect of the brief, not only of the agent)
1. **It built a JSON file and a summary, not the video.** For the kind Khusus the brief says only "Kind: Khusus" in the options; its first paragraph still says "klipian renders it from JSON with a fixed template, so you do not write code". The procedure for the second job (build `remotion/videos/<slug>`) lives only in the skill, which only Claude Code loads. It offered to "invoke the klipian-video skill" and stopped.
2. **The beat `sting` had no narration, and the validator refuses that** ("only the outro may be empty"). The brief's structure table says "a small mascot and the pill" and never says the sting needs a sentence. It still reported "compliance verified" without running `node remotion/validate.mjs`.
3. **Every beat used `socket` as the hero**, for a sleep topic. The catalogue says "if the object is not in the catalogue, write it in `needs` and **use the closest listed thing meanwhile**", and the only hero object is the socket. It also wrote "heat: 0 on sockets (no red glow)" because the colour rule is about electricity.
4. **The brief is electricity-biased**: the colour code ("yellow = electric current, red = heat"), the safety rule ("mains electrical equipment"), the lens rule (a circuit breaker example), and the only example story (a colokan). The kind names `lens` and `loose` are socket words; for a sleep topic the agent guessed ("loose").
5. **The example teaches the old outro**: its last beat has a mascot, a label, a pill and a narration, which the brief's own rule ("loop-back: no mascot, no label, no pill, no voice") and the validator warnings forbid. It has no `sting` beat either.
6. **The answer format fits a chat window, not an agent**: "reply with a single JSON block, no explanation" while an agent writes files and summaries. The sentence that told agents to validate was removed (it named a file that did not exist), and nothing replaced it.
7. **Lists that disagree**: the music tracks in the options, in the answer format and in the catalogue differ (`bed-calm | bed-tech | none` in one place, six beds in another).
8. **Length and repetition**: about 9,000 words; "at most 6 words of screen text" is stated three times, the hard rules are buried between reference tables, and weaker models skim.

## The new brief: structure (one agent-neutral document, written once, built in this order)
**0. Read this first (about 25 lines, the only part a lazy reader needs)**
- Who you are and the deliverable, in two sentences, **without any product name**: "You are an AI agent. You make one short vertical explainer for the channel klipian intip." Then a **mode line** that works for any tool: "If you can read and write files and run commands in the repository `D:\github-repos\klipian`, do **Part A and Part B**. If you can only chat, do **Part A** and print the JSON in your reply."
- The **hard rules in one numbered list of at most 15 lines** (the only rules that cannot be broken): sum of beat seconds equals the duration; the sting beat has the narration "Intip yuk!"; the outro has an empty narration, no mascot, no label, no pill, and the first beat's scene; at most 6 words per screen text; every claim has a real source URL you opened; use the story's `bible: 1`; the hero object comes from the topic (never `socket` unless the topic is an electrical socket or plug); no health, finance or dangerous-instruction topics; never write to `workspace/` and never read or print secrets; no API key; **never say a check passed unless you ran it and pasted its output**.
- **Definition of done** (what to hand back, per mode), and **stop rule**: if a step fails, report the failure and stop; do not claim success.

**Part A: the story (every kind)**
1. The task steps (as today, shorter), the options, the structure (the table below), then **the beat kinds explained** (see C), **the self-check checklist** (see D), then the story's fields and a **valid example** (see E).
2. **Where the answer goes:** in chat mode, one fenced `json` block and nothing else. In agent mode: save the same JSON to `remotion/stories/<slug>.json` (slug: lowercase, hyphens, from the topic), **also print it in a fenced block in the reply**, and never save it anywhere else (not in `remotion/` root, not in `workspace/`).
3. **Validate (agent mode)**: from the repo root, `node remotion/validate.mjs remotion/stories/<slug>.json`; read the whole output; fix every error and re-run until it prints `"ok":true`; warnings are advice, say which you left and why. **Chat mode**: go through the checklist and say that you could not run the validator.

**Part B: the video folder (only when the options say Kind: Khusus; this replaces the skill as the source of truth)**
Numbered steps with the exact commands, working directory and expected result of each: read `remotion/DESIGN.md` sections 0b (style bible) and the rules B1 to the latest; `cd remotion`; `npm run new-video <slug> stories/<slug>.json`; edit `videos/<slug>/index.tsx` and `plan.ts` with the kit (one hero, a diorama stage, the dictionary marks, at most three new assets; reuse before drawing; the theme, stage shape and music from the story's fields once the variety plan has landed); `npm run style-check -- <slug>` (no FAIL allowed; read FLAG, RENDER and HUMAN lines); `npm run style-report -- <slug>`; **render nothing and push nothing**. Then the **narration texts**: for each voice app checked in the options run the one `python -c ... motion.narration_export` command (taken from the skill) and paste the output; tell which tags were used. Finally the **next steps for the person** in plain words: open `/remotion`, choose the folder (full path: `D:\github-repos\klipian\remotion\videos\<slug>`), press "Ambil cerita dari folder", make the voice outside klipian, choose the audio, Cocokkan, preview, render.
- For the Otomatis kind Part B is **absent** (a test checks it).
- **A reporting template** (the agent fills it; no table of ticks without evidence): story path; validator result (pasted); folder path; style-check summary line (pasted); what is not done or not checked; the narration texts.

## C. The kind-specific and topic-neutral rules
1. **Kind Otomatis:** the template can draw only what the catalogue lists. Add: "use `socket` and `lens` **only** for a topic about an electrical socket or plug; for any other topic prefer `chibi` (only if a person is the point), `stack`, `label`, `arrow`, `badge`, `banner`, `source`, list the objects the topic really needs in `needs`, and expect a plain result". Remove "use the closest listed thing" (it is what produced the sockets).
2. **Kind Khusus:** "the video is drawn in code from this story's **texts, timing, claims and music**. The `scene.items` of a beat only need the `banner` (and the `pill` and `mascot` of the sting); do **not** fill the scene with catalogue objects to look busy; **do not use `socket`** unless the topic is a socket; write every object the video must show in `needs` (the builder draws them in Part B)". State it twice: in the options line and at the start of the catalogue.
3. **Beat kinds** as a table in plain words: `hook` (about 3 s, no mascot), `sting` (1 s, narration exactly "Intip yuk!", small mascot + pill), `lens` (the look-inside beat: only if the cause is inside a physical object; otherwise do not use it), `normal` (one step of the explanation: the default), `loose` (only for the "bad case" of a physical object whose variant is loose; for any other topic use `normal`), `result`, `tips` (2 tips; "stop using it / ask a technician" style only where relevant), `outro` (loop-back). Rename nothing in the schema; the table makes the words clear.
4. **Colour code**: make it general ("red only for danger or heat, never decoration; yellow is the channel's accent: use it for highlights and numbered badges"), and move the electricity-specific code into one sub-bullet "if the topic is electrical: yellow = current, red/orange = heat, grey = material, light grey = metal".
5. **Safety**: keep it, written once, topic-neutral first ("no health or finance topics; never teach anything dangerous"), then one electrical sub-bullet ("no instructions to open, modify or bypass mains equipment; tips are 'stop using it, unplug it, ask a technician'").
6. **Lens rule** generalised ("only when the cause is inside a physical object; for a habit, a body, a process or an idea use a flow, a diagram or labels").
7. **Hook length**: the notes of the person may contain a long hook; say "if the person's hook is longer than 3 seconds (about 9 words), shorten it and keep its meaning".

## D. The self-check checklist (in the brief, before the answer format; the agent ticks it with evidence)
A numbered list of 14 items, each **testable**: (1) durations add up to `duration`; (2) first beat is `hook` with no transition, last is `outro`; (3) `sting` is beat 2 with narration "Intip yuk!"; (4) `outro` narration is empty and its items have no mascot, label or pill; its scene equals the first beat's; (5) every screen text, banner, pill, label, label line is at most 6 words; (6) every beat has a `banner` equal to its `text`; (7) at most 3 transitions that are not a cut, each at most 80 % of the shorter neighbour; (8) every claim names existing beat ids and has at least one URL you opened; (9) `bible: 1`; (10) `music.track` is one of the **listed** names (the list is generated from the catalogue, see G); (11) exactly 3 titles, each at most 100 characters, the hashtag rule of the profile holds; (12) no `socket` unless the topic is an electrical socket or plug; (13) at most one `lens` beat; (14) the JSON is plain (no comments, no trailing commas). In agent mode the validator confirms 1 to 10 and 13 and 14; the rest is on the agent.
