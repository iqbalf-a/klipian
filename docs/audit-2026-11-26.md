## The 7 confusions, with what the code shows

1. **Three entries to download from YouTube, plus one dead one.**
   - Edit > Assets: "From YouTube link…" (`addYouTubeBtn`, `ytdl.js`) and "From YouTube, parts only…" (`addYouTubePartsBtn`, `ytparts.js`).
   - Sources: "+ From YouTube" (`sourceYtBtn`, same dialog as the first).
   - Edit > Analyze: a disabled "paste a video link / Download" row saying "isn't available yet". **Removed in this pass** (nothing referenced it).
2. **Parts-only is a separate flow, not an option.** It needs Gemini first, then downloads only picked clips with 20 s padding. It should be one "From YouTube…" dialog with a choice "whole video / only the clips I pick", not two buttons with different mental models.
3. **Render separate vs bulk.** Edit has "Render Result" (`resultRenderBtn`, one) and "Render selected" (`bulkRenderBtn`, many), and "A separate video for each" which creates Results, not renders. The word "separate" names a Result-creation step, so it reads like a render mode.
4. **Bulk exists in four unrelated places:** Results bulk (Edit), clips bulk (Workspace), YouTube bulk upload, and the "bulk render" mentioned in the guide link. Each has its own button style and its own selection model.
5. **Motion, create first.** `STEPS_CUSTOM`: new, brief, story, facts, script, voice, preview, render. The picture is built first, the voice imported and matched after.
6. **Motion, voice first.** Look "ricks" (and `-create ricks`) is voice first by design (rule B46), but the page shows the same step order for it, only the look label says "voice first". Same page, two opposite flows, no visible difference in the steps.
7. **Inconsistent features.** Examples found: two "Download" brief buttons with different meaning (`downloadBrief`, `downloadGeminiBrief`, `postBriefDownload`); two primary-coloured buttons side by side in the Post panel (`postBriefCopy` and `postReplyPaste`, both `.btn.main`, against the rule "one main per area"); the profile chip, theme and guide link repeated per page in HTML instead of one shared header; control heights not uniform (already listed in `docs/ui-design.md`).

## Recommended order

1. One YouTube dialog (whole / clips only), one entry per page. Remove the second Edit button.
2. Motion: show the real order for each look. Ricks gets "voice" before "story"; others unchanged. Needs ian's decision (see below).
3. One word per concept: "Result" (a clip being made) vs "Render" (the action). Rename "A separate video for each".
4. One header partial for all pages; one bulk-bar pattern.
5. Split `server.py` render orchestration out of HTTP (the roadmap item 1).
6. Then the CSS pass (heights, `workspace.css` Tailwind classes).
