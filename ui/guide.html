klipian guide

This page is static: it holds no profile data. Menu names are written exactly as they are in the Google Cloud console (2026) and in klipian, so you can follow them step by step.

A. YouTube: one Google Cloud project per channel

Why one project per channel. The YouTube Data API upload quota is counted per Google Cloud project: what we measured is 100 uploads a day per project. If every channel uses one project, they share that quota. Separate projects also keep the tokens apart, so one channel in trouble does not disturb the others.

Nothing needs to be paid. Do not click Try for free or fill in billing: the YouTube Data API v3 is free inside this quota.

1. Create a project

  1. Open console.cloud.google.com with the Google account you manage all klipian projects from. It does not have to be the channel's owner: the owner only needs to be added as a Test user (step 4).
  2. Click the project picker in the top bar (Select a project) › New project.
  3. Name it, for example klipian-lucu, then Create. Make sure the new project is the one selected in the top bar.

2. Enable the YouTube Data API v3

  1. APIs & Services › Library.
  2. Search for YouTube Data API v3 › Enable.
  3. Check the quota: APIs & Services › Enabled APIs & services › YouTube Data API v3 › Quotas & System Limits, look at the row Video Uploads per day.

3. Consent screen (Google Auth Platform)

  1. Open Google Auth Platform › Get started.
  2. App name: anything (for example klipian). User support email: your email.
  3. Audience: choose External.
  4. Contact information: your email. Agree to the policy, then Create.

The menu on the left is now: Overview, Branding, Audience, Clients, Data Access.

4. Test user: the account that owns this channel

  1. Audience › the Test users section › Add users.
  2. Enter the Google account that owns this channel, then Save.

If that account is not on the list, Google refuses the sign-in with a “not verified / access blocked” message. klipian shows it as Not a test user (red).

5. Data Access: the permissions needed

  1. Data Access › Add or remove scopes.
  2. Tick …/auth/youtube.upload and …/auth/youtube.readonly (if they are not in the list, paste them into Manually add scopes › Add to table).
  3. Update, then Save.

6. Client (Desktop app) and the JSON file

  1. Clients › Create client.
  2. Application type: Desktop app. Any name. Leave the AI-powered agent box unticked.
  3. Create, then click Download JSON right away: the client secret may be shown only once.
  4. Keep the file somewhere safe, for example your private folder. Its name is usually client_secret_….json.

Do not share that JSON file and do not paste it into a chat, an email or a repo. Anyone who holds it can use your project's quota. klipian keeps it only in this profile's folder.

7. Connect in klipian

  1. Open the right channel's profile (the profile's name and colour show in the top corner).
  2. Profile settings › the YouTube account section › Choose client_secret.json… › choose that file. The Client row turns green (Client ✓).
  3. Connect YouTube. The browser opens: sign in with the account that owns this channel, choose the right channel if asked, then allow.
  4. The Account row turns green: Connected ✓ with the channel's name. Done.

Testing status and the audit

  • Testing = reconnect about every 7 days. While the project's status is Testing, the Google token expires after about seven days. klipian marks it Expired (yellow): press Connect again.
  • Uploads from a project that is not audited are locked private. YouTube holds a video uploaded through the API from a project that has not passed the audit as private (“locked private”). So the video arrives, but you have to change its visibility yourself in YouTube Studio, or apply for the YouTube API Services audit so that public uploads are allowed. A publish schedule from klipian does not change this.

B. Statuses and what the colours mean

Profile settings › YouTube account has two rows, and the small dot beside the profile's name uses the same colours.

The Client row (the client_secret.json file)

Client ✓
The file is valid. The Google Cloud project it belongs to is shown, and whether it comes from this profile or from the shared fallback (workspace/secrets).
Client ✕
Not a client_secret.json that can be used (the wrong kind of client, a broken file). Choose again; it must be Desktop app (section 6).
Client
Not chosen yet. Choose client_secret.json…

The Account row

Connected ✓
Connected and the token is accepted. Fully green only when the Client row is green too.
Not connected
No link yet. Choose the client first, then Connect YouTube (section 7). “No client yet” means the client file is not chosen.
Expired
The connection expired (a project in Testing: about 7 days). Press Connect again.
Other channel
The token is valid but belongs to another channel than the saved one. Connect again to accept the new channel, or sign in with the right account.
Not a test user
Google refused the sign-in: add that account in Google Auth Platform › Audience › Test users (section 4), then Connect again.
Offline
Google cannot be reached; the last known status is shown. Try again when the internet is back (Check connection).
The YouTube package is not installed
Run once: .venv\Scripts\python.exe -m pip install -r requirements-youtube.txt

Upload limits

There are two different limits, and klipian says which one was hit (Google's own reason is shown small under the message, with Copy details; everything is also logged in profiles/<id>/youtube.log):

Channel limit (uploadLimitExceeded)
This channel reached its daily upload limit. A new or unverified channel has a lower limit: verify at youtube.com/verify. It usually loosens about 24 hours after the first upload of that run. The bulk queue stops cleanly; the rest is not touched (“not sent”).
Project quota (quotaExceeded)
The Google Cloud project's daily quota is used up; the one that counts is Video Uploads per day (100 per project; refused attempts count too). It resets every midnight Pacific time; klipian gives that hour in your computer's time (e.g. 14:00 WIB during the US summer, 15:00 WIB during the winter).
“Slow down” (rateLimitExceeded)
YouTube asks to slow down. In a bulk upload klipian waits 30–90 seconds and sends that file again a few times; it stops only if the file is still refused.

To tell them apart, open Google Cloud Console › APIs & Services › YouTube Data API v3 › Quotas & System Limits: if Video Uploads per day is full (e.g. 100/100), it is the project quota. If that row still has room (e.g. 12/100) but uploads are refused, it is the channel limit, which that table does not show. Queries per day is not used by uploads (videos.insert counts only in Video Uploads per day; 12 uploads plus the status checks use 15 queries), so that row almost always has room. In the bulk upload dialog, the quota row also shows how many videos this channel uploaded in the last 24 hours; a newly connected channel gets a hint when a day passes about 6 videos.

C. Claude API (Find clips with Claude)

Optional. Everything works without it: Copy brief or Download file on the Analyze screen, paste it into Claude on the web, then paste its answer back into klipian. That manual way needs no key.

Setting the key

  1. Open console.anthropic.com › API Keys › create a key. The account must have credit (top up in Billing), or the calls are refused.
  2. Install the package once: .venv\Scripts\python.exe -m pip install -r requirements-claude.txt
  3. In klipian: Profile settings › Anthropic API › paste the key › Save key › Test. The key is kept on the local server and is never sent to the browser again. Do not paste it into a chat or a repo.
  4. Choose the Model (default: the newest Opus on your account) and the Effort. The table below shows the usage per month.

Using it

  1. On the Analyze screen, press Find clips with Claude.
  2. The dialog shows the model, the number of input tokens and the estimated cost before anything is sent. It is an estimate: the thinking and answer tokens are known only when it is done.
  3. Press Send to Claude. The result arrives like a manual import (AI suggestions on the Clips screen). Cancel stops it.

The rubric used (dialog, gameplay, or your own rubric in workspace/rubrics) is chosen in Profile settings, or per brief on the Analyze screen.

D. Download from YouTube

On the Assets screen (or Analyze) choose Add from YouTube, paste one video link, Check, then Download. The file goes to the profile's sources folder as “channel - title.mp4” and its credit is filled in automatically.

What it needs

  1. yt-dlp: .venv\Scripts\python.exe -m pip install -r requirements-download.txt (it installs yt-dlp[default]). YouTube changes often: if a download fails, press Update yt-dlp in the dialog.
  2. Node.js (or deno) on the PATH, from nodejs.org. Without a JavaScript runtime, YouTube refuses long downloads (HTTP 403). The dialog shows the runtime in use beside the yt-dlp version; if it says “no JS runtime”, install Node.js and then Update yt-dlp.
  3. ffmpeg (klipian needs it already) to join the video and the sound.

Tips

  • An 83-minute video at 1080p can be about 1.8 GB. Choose 720p (smaller) on the preview card if space or time is short; the size is updated.
  • When it fails, a friendly message is shown with a small line holding the original error and a Copy details button. Copy and send that if you need help. The log is also in ytdl.log in the profile's folder.
  • Private, age-restricted or members-only videos cannot be downloaded: klipian does not sign in.

A credit is not a permission. Filling in the source credit only gives attribution; it does not give you the right to reuse someone else's video. Download only content you are allowed to use.

E. Profiles and Guest

  • One profile = one channel. Each has its own sources, projects, renders, upload schedule, YouTube account and settings (watermark, rubric, hashtags). Your own rubrics and the transcript cache are shared by all profiles.
  • The profile is chosen per browser tab: two tabs can use two channels at once. The profile's name and colour always show in the top corner, so you do not work on the wrong channel. There is no password: klipian runs on your computer and a profile only keeps the data apart.
  • To make a new profile: the profile picker › New profile (name, colour). Then choose the rubric in Profile settings and connect YouTube (section A).
  • Guest: for a quick try. It can edit, render, download from YouTube and use Find clips with Claude (its key is kept in the workspace and shared by all profiles; set it from a normal profile). It has no upload schedule, no YouTube account and no settings. Clear guest data in the profile menu moves everything Guest made to the Recycle Bin.

F. Bulk render

The Clips screen reads from top to bottom:

  1. Choose moments: tick the AI suggestions in the list. Then take one of two ways:
    • One video from these moments (Add N to this Result): the ticked suggestions are joined into the open Result. One render = one file.
    • One video per moment (Make N Results, one per moment): each suggestion becomes its own Result and takes the output format of the open Result. Render = N files.
  2. Results: the list of clips to render. Each row shows the duration, the output format, the framing and when it was last rendered. Tick = included in Output format / Delete / Render; Editing = the Result open below it. Quick picks: Select all from this brief, All, None.
  3. Output format…: one format (Picture, Background, Position, Resolution, Quality) for every ticked Result, with a preview of one sample clip. “Keep each Result's own” leaves one control as it was, so for example only Picture is changed. The Put each Result's intro… box puts each Result's intro (the one it already has from the JSON import, the Intro & notes panel) on its video for a few seconds.
  4. Render selected (N): the plan dialog shows each clip with its format, the estimated time and the AI Framing option for clips without framing. The results are on the History screen.

Bulk upload to YouTube (in Workspace, tick the clips, Upload to YouTube) has two modes: Schedule (default: each clip goes public on its date and time) and Publish now: every selected video goes public right away, one after another as each finishes uploading, with no date. This mode always starts from Schedule, warns you and asks for confirmation; it cannot be undone from klipian once a video is public. Shorts that go public together tend to compete, so scheduling them with a gap is usually better.

In Schedule mode, the Schedule section fills the date and time of the clips that have none: the start date and time, then Gap between clips in minutes, hours or days (default days; a whole number, 0 or more, 0 = all the same; the start time must be more than 5 minutes ahead, a gap in minutes has no minimum). Clips that already have a date and time keep them, unless Also change clips that already have a date and time is ticked: then every selected clip is rescheduled from that date and time with the same gap, and their old times are replaced.

Delete selected and the ✕ on each row delete the Result (with Undo for a few seconds). Rendered files and upload schedule rows are never deleted with it.

Automatic framing (the 00:00 point you have not touched) uses the full height of the video with the width of the picture shape, centred. Points you set yourself do not change.

G. Post text for one clip (no API key)

For a clip you cut yourself (moments typed by hand) or any Result: the Result title, the upload title, the caption, the hashtags and the take can be written by Claude through chat, by copy and paste. No API key and no cost beyond your subscription.

  1. Open the Render screen with that Result, the Post text panel, the Write it with Claude section.
  2. Press Copy brief for this Result (or Download). It is short: only this clip's words (with the corrections, timed from the start of the clip), the voice signals in it, the source context, the rubric parts Judul dan hook, Teks posting and Sudut pandang, the profile's hashtag rules, and the answer format. The rubric used: the profile's choice, or the choice on the Analyze screen.
  3. Paste it into Claude on the web (a new chat) and send.
  4. Copy the answer, then in klipian press Paste reply… and paste. Claude's whole message is fine: its JSON block is found automatically, and common slips (a trailing comma, .replace) are fixed and reported.
  5. The fields filled: the Result title (the name in the list and the file name), Post text (title, caption, hashtags) and Intro & notes (take, intro, notes). If some already have content, klipian asks Replace what is written? with the list of fields. Undo restores everything.

Where the buttons are: in the Post text panel (at the top of the Render screen); on the Clips screen each Results row shows post ✓ title or no post text and has a Post text… button; the Open Result panel has Write post text with Claude; and for several Results at once, tick their rows and press Write post text… in the bar under the list: one brief holds every ticked Result (each clip with its id) and Claude answers with one entry per id. Fields that already have content are asked about per Result, and one Undo restores everything.

If the answer lacks a field, the message says which one (for example post.caption): ask Claude to answer again with the complete JSON block. A final title longer than 100 characters gets the usual warning. If that Result was rendered before, its upload schedule row uses the new text at the next render. This panel does not exist for the Guest profile.

Thumbnail text: the Find clips brief (pasted, or automatic with Claude/Gemini) asks Claude to write a thumb per clip: 3 to 6 words, one whole phrase, optionally one key word between *stars*. The order of the text on the card: the Thumbnail text you type in Detail, then the AI's thumb, then the hook quote, then the title. If the text is a cut title or hook, the row is marked text cut: check.

Thumbnail to YouTube: after an upload, klipian waits for YouTube to finish processing the video (up to about 7 minutes; the upload queue keeps going), then sends the thumbnail. The result is written in the clip's Detail. If it fails, or the thumbnail in Studio is still the automatic frame, press Re-send thumbnail in Detail (50 quota units, only when you press it). klipian cannot check from YouTube whether the thumbnail changed: "sent" means YouTube answered OK. If the thumbnail picture could not be made during the render (the video is still made), the row is marked no thumbnail: reason, the reason is also in thumbnail.log in the profile's folder; press Make thumbnail in Detail.

H. Motion video: from a topic to Clips (no API key)

The Motion page (/create-motion) makes an animated fun-fact video (9:16, 30 fps, with sound effects) from one topic. klipian works on this computer; its AI is Claude Code on this computer, so there is no API key. It needs Node.js and npm install in the remotion/ folder (once).

The page has eight steps. Steps are folded: only the step being worked on is open, a finished step shows a one-line summary. Next step at the top always names the one thing to do, and its button opens that step.

  1. New video: write the topic (e.g. "fakta seru tentang colokan listrik panas"), choose 30, 45 or 60 seconds, and the video options: loop, "Intip yuk!", music, and the voice apps you use. These options shape the brief.
  2. Brief: Copy the full brief (or download it) and paste it into Claude Code opened in the klipian folder. It searches the web, writes the story and makes the video folder in remotion/videos/. Change the video options changes those options and the brief follows.
  3. Load the story from the Claude Code folder: choose the folder it made, then Load the story from the folder. The story is checked like an AI answer; when something is wrong, klipian writes a fix message to paste into Claude Code. The storyboard (narration, screen text, the time of each beat) is in this step: edit the texts, Save texts, then Make the storyboard pictures if you want to see them. If story.json in the folder changes, the page asks for the story to be loaded again and no render is offered before that.
  4. Check the facts and the title (required): open every source, then Correct or Reject (the date is kept), or All correct after you opened all the sources (klipian asks once: "Did you open the sources?"). A rejected claim makes a revision brief only for the beats that use it. Then choose one of the three titles.
  5. Voice script: the text for the voice apps you chose, used before the voice is made. VoiceStudio reads every character you paste, so its text is plain: only the narration sentences, with no part titles, pauses or tags. A long text is split into plain parts that can be copied or downloaded one by one (_1.txt, _2.txt). ElevenLabs and Google AI Studio use tags from their own official lists; the settings and notes are beside the text box, not inside it.
  6. Import the voice and match it: use your own recording (write the file's path, or choose a file) or, if you installed a local text-to-speech engine, Make it with local TTS (its command is in workspace/machine.json as motionTts, e.g. mytts --in "{text}" --out "{out}"). Match with the narration uses faster-whisper on this computer: every word gets its time, every beat lasts as long as its narration, the captions light up word by word, and the sound effects and the music duck under the voice. The video length shown everywhere is the voiced length, not the first plan.
  7. Preview: a half-size draft with the voice, the effects and the music.
  8. Render: allowed only when every claim is checked, a title is chosen, the story in the folder is the one that was loaded, and the voice (if any) is matched (the server refuses, not only the button). The render joins the same heavy queue as clip renders, with progress, time left and Cancel. The result becomes a Clips row (the out/motion/ folder) with the chosen title, the description, the hashtags and the sources of the checked claims, ready to schedule or upload like any other clip.

Order: picture first or voice first. Choose it when you create the video (the Order select; look Ricks sets it to Voice first). The eight steps above are picture first, the way every video made before this choice works: Claude Code builds the story and the picture in one go, then you add the voice. With voice first the voice comes before any drawing, so every shot lands on a word: the Brief asks Claude Code only for the story and the narration text (stage 1); you paste the story in the step Paste the story and the storyboard, check the facts, make the voice from the script and match it; then the step Build the picture to the voice gives a second brief (stage 2, with the voice-timed story inside it, so any Claude Code session can use it). Choose the folder it made, load the story, press Match with the narration once more (the story file changed), then Preview and Render. The -create command is separate: it is one stage, except -create ricks, which waits for the voice (wav=).

Video kind. The main flow is Custom: the video is built in a Claude Code session (read remotion/DESIGN.md). The Template kind (klipian's template from a pasted AI answer) is hidden under Advanced settings and still works for old videos.

Things that are not in the library yet are not invented by the AI: it lists them in needs.
